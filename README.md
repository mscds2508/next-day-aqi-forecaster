# Air Quality Index (AQI) Prediction — India

Predict a city's Air Quality Index (AQI) from pollutant concentrations and
time-based features, so poor air quality can be flagged in advance instead
of only being reported after the fact.

## Problem Type
**Supervised Machine Learning — Regression**
(can be adapted to classification by predicting `AQI_Bucket` instead of `AQI`)

## Dataset
[Air Quality Data in India](https://www.kaggle.com/datasets/rohanrao/air-quality-data-in-india) (Kaggle)
Day-wise pollutant readings from monitoring stations across major Indian
cities (Delhi, Mumbai, Bengaluru, Chennai, etc.), spanning multiple years.

Download `city_day.csv` from Kaggle and place it in the `data/` folder
before running the pipeline.

## What Gets Predicted
- **Target:** `AQI` — a continuous numeric value
- **Input features:** pollutant concentrations (PM2.5, PM10, NO2, NOx, NH3,
  CO, SO2, O3, Benzene, Toluene, Xylene), City, and engineered time features
  (Month, Day of Week, Season, previous day's AQI)

## Project Structure

```
aqi_project/
├── data/                       # raw and cleaned CSV files (not committed)
│   ├── city_day.csv            # <- download from Kaggle, place here
│   └── city_day_clean.csv      # generated by preprocessing.py
├── models/
│   └── aqi_model.pkl           # trained model (generated)
├── outputs/
│   ├── metrics.json            # evaluation results (generated)
│   └── actual_vs_predicted.png # evaluation plot (generated)
├── src/
│   ├── config.py               # paths, column names, hyperparameters
│   ├── data_loader.py          # reads raw / clean CSVs
│   ├── preprocessing.py        # cleaning, missing values, duplicates
│   ├── feature_engineering.py  # calendar features + lag feature
│   ├── train.py                # builds pipeline, trains, saves model
│   ├── evaluate.py             # computes RMSE/MAE/R2, saves plot
│   └── predict.py              # loads model, predicts on new data

└── README.md
```

Each module in `src/` has a single responsibility — swap out any one piece
(e.g. try a different model in `train.py`, or add features in
`feature_engineering.py`) without touching the rest of the pipeline.

## Setup

```bash
pip install -r requirements.txt
```

Place the Kaggle `city_day.csv` file into the `data/` folder.

## Usage

**Run the full pipeline (preprocess → train → evaluate):**
```bash
python main.py
```

**Or run each stage individually:**
```bash
python -m src.preprocessing      # cleans raw data -> data/city_day_clean.csv
python -m src.train               # trains model -> models/aqi_model.pkl
python -m src.evaluate            # evaluates model -> outputs/metrics.json
```

**Predict AQI for new data:**
```bash
python -m src.predict
```
Edit the sample row in `predict.py`, or import `predict_aqi()` into your
own script and pass a DataFrame with the required feature columns
(see `config.ALL_FEATURES`).

## Model
Baseline: **Random Forest Regressor** (scikit-learn), wrapped in a
`Pipeline` with one-hot encoding for categorical features (`City`, `Season`).
Hyperparameters are set in `src/config.py`.

## Evaluation Metrics
- **RMSE** (Root Mean Squared Error)
- **MAE** (Mean Absolute Error)
- **R²** (coefficient of determination)

Results are saved to `outputs/metrics.json`, and an actual-vs-predicted
scatter plot is saved to `outputs/actual_vs_predicted.png`.

## Notes & Limitations
- Missing pollutant values are imputed using city-level medians.
- The lag feature (`AQI_lag1`) assumes chronological, per-city continuity —
  gaps in monitoring station data may weaken this signal.
- This is a baseline model. Next steps could include trying
  XGBoost/LightGBM, tuning hyperparameters, or reframing as a time-series
  forecasting problem (e.g. with LSTM) for multi-day-ahead prediction.

## Possible Extensions
- Predict `AQI_Bucket` (categorical) instead of raw AQI for a classification variant.
- Add weather data (temperature, humidity, wind speed) as external features.
- Build a simple dashboard/API endpoint around `predict.py` for live scoring.
